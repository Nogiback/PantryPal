# PantryPal Project Overview

This document provides a comprehensive overview of the PantryPal project, breaking down both the high-level architecture and design decisions, as well as the low-level modules, functions, and data structures.

---

## 1. High-Level Overview

### Purpose
PantryPal is a modern, responsive web application designed to help users manage their pantry inventory and discover recipes based on what they already have at home. By leveraging AI (AWS Bedrock), the application generates custom recipes to minimize food waste, while also allowing users to track ingredient expiration dates and manage their household grocery needs efficiently.

### Architecture
PantryPal's frontend is a Single Page Application (SPA) built using a modern React stack. The project is structured to separate concerns into components, state management, and external services.

- **Frontend Framework**: React 19 combined with Vite for fast builds and Hot Module Replacement (HMR).
- **State Management**: Redux Toolkit is utilized for global state handling (e.g., pantry items, user preferences, recipe results).
- **Styling**: TailwindCSS is used for utility-first styling, complemented by custom CSS for complex animations (GSAP, Framer Motion) and Radix UI primitives for accessible, unstyled components.
- **Authentication**: AWS Cognito handles user authentication and session management.
- **Backend Integration**: The frontend communicates with an AWS API Gateway backend, utilizing AWS Lambda for business logic and AWS Bedrock for AI-driven recipe generation. A local server proxy (`claude-proxy.mjs`) is used for development routing.
- **Deployment**: AWS Amplify provides fully automated CI/CD for continuous deployment of the frontend assets.

### Design Decisions
1. **Component-Driven UI**: A strict adherence to atomic design principles using `shadcn/ui` style components (Radix UI + Tailwind), ensuring consistency and reusability.
2. **AI-First Recipe Generation**: Instead of relying solely on static third-party recipe databases, the application integrates AWS Bedrock (Claude model) to generate dynamic, personalized recipes based on exact pantry contents.
3. **Optimistic UI Updates**: Using Redux Toolkit to provide immediate feedback to user actions (like adding/removing ingredients), syncing with the backend asynchronously for a smooth user experience.
4. **Rich Aesthetics**: Incorporation of GSAP and Framer Motion for micro-interactions and smooth page transitions, elevating the "premium" feel of the application.

## 2. Low-Level Overview

### Modules & Directories
- `src/components/`: Contains the majority of the reusable React components.
  - `ui/`: Base-level, generic components (Buttons, Inputs, Modals) usually built on top of Radix UI.
  - `views/`: Higher-level page components (e.g., `DashboardView.tsx`, `FavoritesView.tsx`) that act as containers for specific routes or states.
- `src/store/`: The Redux store configuration.
  - `slices/`: Individual Redux slices managing specific domains of state (e.g., pantry ingredients, AI generated recipes, user auth state).
  - `hooks.ts`: Typed Redux hooks (`useAppDispatch`, `useAppSelector`).
- `src/services/`: Functions dedicated to interacting with external APIs or backend endpoints. Includes AI proxy calls and external recipe integrations (e.g., Spoonacular mock/real integrations).
- `src/types.ts`: TypeScript interfaces defining the application's core data models.
- `server/`: Contains Node.js/Express proxy scripts (`claude-proxy.mjs`, `user-data.mjs`) to handle local development CORS bypassing and mock data serving.

### Core Data Structures
Defined in `src/types.ts`, the core data structures include:
- `Ingredient`: Represents an item in the pantry. Contains fields like `id`, `name`, `quantity`, `unit`, `expiryDate`, `category`, and `inFreezer`.
- `Recipe` & `RecipeDetails`: Standard recipe objects returned from external APIs, containing standard fields (title, image, used/missed ingredients, instructions).
- `AiRecipe`: A structured object generated by the AWS Bedrock proxy containing `title`, `servings`, `estimatedTime`, `ingredients` (with a boolean `fromPantry` flag), and `instructions`.
- `MealPlanRecipe`: A wrapper object combining standard recipes or AI recipes for meal planning features.

### Key Functions & Flows
1. **Pantry Management (`AddPantryItemModal.tsx`, Redux Slices)**:
   - Users input an ingredient.
   - The component dispatches an action to the Redux store.
   - The store updates the local state while a thunk asynchronously calls the backend API to persist the change.
2. **AI Recipe Generation**:
   - The user requests a recipe based on selected pantry items.
   - A service function sends the selected `Ingredient` objects to the backend proxy/API.
   - The backend constructs a prompt for AWS Bedrock, retrieves a response, parses it into an `AiRecipe` JSON structure, and returns it to the frontend.
   - The frontend renders the recipe in a `CookResultModal.tsx` or `RecipeDetailsSheet.tsx`.
3. **Authentication Flow**:
   - Integrated with `amazon-cognito-identity-js`.
   - On load, the app checks for a valid session token. 
   - API calls are intercepted to append the Bearer token before reaching the AWS API Gateway.
